# selfheal/ — guarded auto-remediation for a Post Fiat validator and sentry

`pft-selfheal` watches one postfiatd container once a minute and, in enforce mode, runs **at most one** of two
remediation actions when a known failure persists. Its guards and budget keep it out of restart loops. The default is
`MODE=dryrun`: it decides and reports what it would do, and does nothing else.

| file | what |
|---|---|
| `pft-selfheal.sh` | runner: observe, decide (via the helper), act, journal, textfile metrics; `status`, `reset`, `pull`, `validate` |
| `selfheal_decide.py` | decision core, Python 3 stdlib only: detectors, guards, backoff, K-per-24h budget, circuit breaker |
| `pft-selfheal.env.example` | `/etc/pft-selfheal.env` with every key at its default |
| `systemd/pft-selfheal@.{service,timer}` | one run per minute per container (`pft-selfheal@postfiatd`, `pft-selfheal@postfiatd-sentry`) |
| `systemd/pft-selfheal-pull@.{service,timer}` | validator only: copies the sentry's textfile (the sentry has no Prometheus) |
| `../alerts/selfheal.rules.yml` | the two alerts; `../alerts/selfheal.tests.yml` promtool tests (generated by `tests/gen_rule_tests.py`) |
| `tests/test_selfheal.py` | offline suite: decision core in-process, the runner against stubbed docker / curl / pft-maint / pft-egress |
| `tests/mutate.py` | mutation harness with baseline, timeout and orphan controls |

## What it detects (first match wins)

| detector | condition (defaults) | action |
|---|---|---|
| `container_down` | container missing or not running | `up` |
| `rpc_failures` | `RPC_FAILS`=3 consecutive failed `server_info` samples | `restart` |
| `stale_ledger` | validated ledger seq unchanged for `STALE_SEC`=300 s | `restart` |
| `stuck_state` | `server_state` not full/proposing/validating for `STUCK_SEC`=600 s | `restart` |
| `zero_peers` | 0 peers for `ZERO_PEERS_SEC`=600 s | `restart` |

Observation uses only what the other add-ons already use: `docker inspect`, and `docker exec NAME curl ... server_info`
against the container's loopback admin port (the same exec shape as pft-statewatch and pft-peerwatch, so the
AppArmor and seccomp profiles see nothing new). Only when the local sample looks stalled does it send one
`server_info` to `REF_URL`, the network-stall reference.

## Actions (the only two)

- `up`: for a compose container, `docker compose -p P --project-directory D -f F1 -f F2 ... up -d --no-recreate SERVICE`,
  with every file from the container's own compose labels, so the resource settings (cpu_shares, mem_reservation)
  and the confinement overrides are kept. The labels are cached in `STATE_DIR` while the container exists, because a
  removed container no longer has them. For a `docker run` container, `docker start NAME`.
- `restart`: `docker restart -t RESTART_TIMEOUT NAME`.

`pft-egress reapply --container NAME` runs after every action. Nothing else is ever executed: no ad-hoc
`docker exec` for remediation, no key or token file read, no recreate, no image pull.

## Guards (any one suppresses the action, checked in this order)

1. **breaker**: open after the budget was spent; only `pft-selfheal reset` closes it.
2. **maintenance**: `pft-maint active` (a valid planned-maintenance window).
3. **lock**: any `pft-maint lock list` entry (data-collection locks). An unreadable lock state counts as a lock.
4. **grace**: no RPC-based action for `GRACE_SEC`=900 s after the container started (`container_down` is never graced).
5. **network stall** (`stale_ledger`, `stuck_state`): if the reference is not more than `REF_LAG`=5 ledgers past our
   stall point, the whole network is stalled and a restart would not help. No reference answer counts as a stall.
6. **backoff**: `BACKOFF_SEC`=600 s after an action, doubled for each action in the last 24 h, capped at 7200 s.
7. **budget**: `MAX_ACTIONS`=K=3 actions per rolling 24 h. The next needed action opens the breaker instead.

## Commands and exit codes

```
sudo pft-selfheal run [--container NAME] [--dry-run] [--textfile-dir DIR] [--stdout]
     0 decided (healthy, suppressed or acted ok), 1 action failed, 3 usage/config, 5 state unreadable (refuses to act)
sudo pft-selfheal status [--container NAME] [--json]
     0 healthy/acted, 1 suppressed or would act, 2 breaker open, 4 no or stale decision
sudo pft-selfheal reset [--container NAME] --reason "text"     closes the breaker, clears the 24 h budget
sudo pft-selfheal pull [--container NAME]                       validator: fetch + validate the sentry's textfile
pft-selfheal validate FILE NAME                                 0 ok, 2 rejected (reason on stdout)
```

`STATE_DIR` (`/var/lib/pft-selfheal`) holds `state-NAME.json` (counters, action times, breaker), `last-NAME.json`
(the last decision with its observation), and `journal-NAME.jsonl`, an append-only log of every non-healthy decision,
action, action result and reset.

## Metrics and alerts

Textfile `pft_selfheal_NAME.prom`: `pft_selfheal_up`, `_run_timestamp_seconds`, `_enforce`, `_verdict{verdict}`,
`_detector{detector}`, `_actions_24h`, `_max_actions`, `_actions_total`, `_breaker_open`. There are two alerts and no
more: **PFTSelfhealBreakerOpen** (critical, 1m) and **PFTSelfhealStale** (warning: run failing or older than 5 min,
5m). A single action does not page: the restart is already visible to the container and node alerts, and it is
recorded in the journal.

## Runbook

- **PFTSelfhealBreakerOpen**: selfheal used its K actions in 24 h and the fault is still there. Run
  `sudo pft-selfheal status --container NAME` and read `journal-NAME.jsonl` (detector, detail, each action's rc and
  output). Fix the cause by hand: `sudo postfiat-health`, `docker logs`, `sudo pft-egress status`, peers. Then run
  `sudo pft-selfheal reset --container NAME --reason "what was fixed"`. Resetting without a fix just spends K more
  actions.
- **PFTSelfhealStale**: `systemctl status pft-selfheal@NAME.timer`, and `sudo pft-selfheal run --container NAME
  --dry-run --stdout` to see the error (exit 3 = conf, 5 = state file). For the sentry, also check
  `pft-selfheal-pull@postfiatd-sentry.timer` on the validator.
- **Planned work**: open a `pft-maint` window (or a `pft-maint lock`) first; selfheal then records `suppressed` and
  takes no action.
- **Switching modes**: set `MODE=enforce` in `/etc/pft-selfheal.env` only after a dry-run period with no unexplained
  `would_act` verdicts (`command grep would_act /var/lib/pft-selfheal/journal-NAME.jsonl`).
